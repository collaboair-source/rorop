## 1. 요약

강아지의 소리를 사람의 언어로 "번역"하는 것은 과학적으로 아직 불가능하다. 그러나 반대 방향, 즉 **강아지가 내는 소리와 몸짓의 패턴을 사람이 알아볼 수 있는 형태(시각·확률·근거)로 바꿔 주는 것**은 20년 넘게 쌓인 동물행동학·생물음향학 연구로 충분히 뒷받침된다.

- 짖음은 단어가 아니라 **등급 신호(graded signal)** 다. 방해·경계 상황에서는 낮고 거칠고 빠르게, 놀이·고립 상황에서는 높고 맑고 변조가 크게 나온다 (Yin & McCowan 2004).
- 사람은 훈련 없이도 **음높이·음색·반복 간격** 세 축으로 짖음의 상황과 감정을 우연 이상으로 맞춘다 (Pongrácz 2005, 2006). 기계학습은 6~7가지 상황을 43~56%로, 딥러닝은 그 이상으로 분류한다 (Molnár 2008; Larrañaga 2015; Gómez-Armenta 2024).
- 사람 음성으로 사전학습한 모델(Wav2Vec2)이 개 소리 전용 모델보다 잘 작동한다 (Abzaliev 2024). 2025년부터 대규모 공개 데이터셋(Barkopedia, EmotionalCanines)이 등장했다.
- 표정·꼬리·자세는 감정 방향(정서가)과 강도(각성)의 단서지만, **단일 단서로는 진단이 불가능**하고 조합해야 한다 (Bremhorst 2022).

BarkLens는 이 근거를 그대로 제품 원칙으로 옮긴다. **"번역기"가 아니라 "렌즈"**: (1) 소리를 보이게 하고 → (2) 상황을 확률과 근거로 읽어 주고 → (3) 우리 강아지의 기준선을 학습하고 → (4) 보호자의 대응을 안내한다. 이 문서는 시장·근거·제품·데이터/AI·기술·사업·로드맵·리스크를 정의하며, 동봉한 샘플 앱은 규칙 기반 엔진으로 전체 흐름을 이미 구현한다.

## 2. 배경과 문제 정의

### 2.1 왜 지금인가

| 지표 | 값 | 출처 |
|---|---|---|
| 국내 반려가구 (2024년 말) | 591만 가구, 전체의 26.7% | 쿠키딜 정리(농식품부 자료) |
| 반려인 | 1,546만 명 (인구의 약 30%) | 동일 |
| 국내 반려동물 시장 | 2022년 8.5조 → 2032년 21조 원 전망 | 데일리벳 |
| 정부 목표 | 2027년 15조 원 | 뉴스핌·리치펫 |
| 산업 흐름 | 사료·용품 → AI 헬스케어·펫테크로 밸류체인 확장 | ZDNet Korea |

- **기술 전환점**: 온디바이스 오디오 모델(YAMNet/TFLite), 음성 파운데이션 모델 전이학습, 바이오어쿠스틱 파운데이션 모델(NatureLM-audio, ICLR 2025)이 동시에 성숙했다.
- **데이터 전환점**: Barkopedia(IJCAI 2025 챌린지), EmotionalCanines(ACM MM 2025), Abzaliev 2024 데이터셋 등 라벨된 개 발성 데이터가 공개되기 시작했다.
- **시장 검증**: 국내 스타트업 펫펄스(Petpuls)가 CES 2021 혁신상을 받으며 "짖음으로 감정 읽기" 수요를 확인했고, 미국 Traini는 앱으로 바이럴을 만들었으며, 바이두는 동물 언어 변환 특허를 출원했다.

### 2.2 보호자의 문제 (Jobs-to-be-done)

1. **"왜 짖는지 모르겠다."** 경계인지, 심심한 건지, 무서운 건지 구분이 안 되어 대응(무시/달래기/훈련)이 엇갈린다.
2. **"혼자 두면 어떤 상태일까."** 분리불안 의심. 외출 중 짖음·낑낑의 양과 성격을 알고 싶다.
3. **"이웃 민원."** 언제 얼마나 짖는지 객관적 기록이 없다.
4. **"훈련·병원에서 설명하기 어렵다."** 전문가에게 보여 줄 근거 자료가 없다.
5. **"몸짓 신호를 놓친다."** 카밍 시그널·경계 신호를 못 읽어 물림 사고·스트레스 누적으로 이어진다.

### 2.3 기존 접근의 한계

| 제품 | 방식 | 주장 | 한계 |
|---|---|---|---|
| Petpuls (한국, 목걸이) | 짖음 음성 인식, 5감정 | 정확도 90% (서울대 검증 인용), 50견종 1만 샘플 | 감정 5개 고정, 근거 비공개, 하드웨어 필수 |
| Traini (미국, 앱) | 멀티모달 LLM, 12감정 | 정확도 81.5%, 120견종 | 행동 전문가들이 "위험한 과잉 확신" 지적, 맥락 무시 |
| Baidu (특허) | 음성+몸짓+생체 신호 변환 | — | 제품 미출시 |
| 토킹 버튼(FluentPet 등) | 개가 버튼을 눌러 단어 표현 | — | 개의 발성 해석과 무관 |

공통 문제: **"번역"이라는 프레임**이 과학이 보여 준 것(등급 신호, 맥락 의존, 개체 차이)과 어긋나고, 틀린 판독이 "편안함"으로 나오면 보호자가 스트레스 상황에 개를 계속 노출시키는 **복지 위험**이 생긴다. BarkLens는 확률·근거·불확실성을 그대로 보여 주는 정직한 설계로 차별화한다.

## 3. 과학적 근거 요약

(상세 정리와 DOI는 02 문서 참조. 아래는 제품 결정에 직접 쓰인 결론만.)

| # | 결론 | 근거 | 제품 반영 |
|---|---|---|---|
| R1 | 짖음은 맥락에 따라 음향이 달라지는 등급 신호. 방해=거칠고 낮고 변조 적음, 놀이·고립=맑고 높고 변조 큼 | Yin 2002; Yin & McCowan 2004 (10마리 4,672회) | 3축 지문의 "음색·변조" 축 |
| R2 | 사람은 6가지 상황을 우연 이상으로 분류하고, 감정 평가는 F0·최고주파수·짖음 간격에 상관. 낮고 빠름=공격, 높고 간격 김=두려움, 높고 빠름=놀이 | Pongrácz 2005, 2006; Molnár 2010(시각장애인도 동일) | 규칙 엔진의 목표값 표, 근거 문장 |
| R3 | 짧을수록 긍정, 높을수록 강렬. 사람 목소리와 같은 규칙 | Faragó 2014; Bálint 2022 (fMRI) | 길이·음높이 해석 문구 |
| R4 | 기계학습: 6상황 43% / 개체 52% (Molnár 2008), 7상황 55.5% · 성별 85% · 나이 80% (Larrañaga 2015), 딥러닝으로 상회 (Gómez-Armenta 2024, 113마리 19,643회) | 동일 | 정확도 목표 및 마케팅 문구 상한 |
| R5 | 사람 음성 사전학습 모델(Wav2Vec2) 전이가 개 소리 전용 모델보다 우수 | Abzaliev 2024 | 모델 v1 설계 |
| R6 | 개체별 고유 특징 존재(개도 사람도 개체 구분 가능) | Yin & McCowan 2004; Molnár 2008, 2009 | 개체 기준선 자동 학습 |
| R7 | 으르렁은 맥락(음식 지키기/위협/놀이) 정보를 담고 짧고 느리게 박동하면 놀이 | Faragó 2010, 2017 | 으르렁 예외 처리 |
| R8 | 낑낑은 최대 3개 기본주파수, 초고음은 23 kHz까지 | Sibiryakova 2020 | 48 kHz 샘플링 권장, 휴대폰 한계 명시 |
| R9 | 분리 상황에서 낑낑=두려움, 짖음=좌절·요구 성향 | Lenkei 2018, 2021 | 부재 모니터 모드 해석 |
| R10 | 꼬리 좌우 편향: 오른쪽=접근(보호자), 왼쪽=회피(낯선 개). 개도 이를 지각 | Quaranta 2007; Siniscalchi 2013; Ren 2022 | 몸짓 단서 카드 |
| R11 | DogFACS: 귀 앞으로 모음=긍정 기대, 눈 깜빡임·입 벌림·코 핥기·귀 납작=좌절. 단일 표정만으로는 진단 불가 | Bremhorst 2019, 2022; Waller 2013 | 단서 조합 판단, 신뢰도 경고 |
| R12 | 카밍 시그널(고개 돌리기·코 핥기·정지) 이후 공격적 상호작용 감소 | Mariti 2017 | 카밍 시그널 안내 문구 |
| R13 | 이미지 딥러닝으로 긍정 기대/좌절 89% (래브라도 29마리), 얼굴 랜드마크 데이터셋 공개 | Boneh-Shitrit 2022; Martvel 2025 | v2 카메라 모듈 |

## 4. 제품 비전과 포지셔닝

**비전**: "우리 강아지가 지금 어떤 상태인지, 근거를 갖고 알아차리는 보호자를 만든다."

**한 줄 정의**: BarkLens는 강아지 소리와 몸짓의 패턴을 실시간으로 시각화하고, 동물행동학 근거에 따라 상황(경계·놀이·외로움·요구·두려움)의 확률을 보여 주며, 우리 강아지의 기준선을 학습해 갈수록 정확해지는 반려견 이해 앱이다.

**포지셔닝 (번역기 ↔ 렌즈)**

| | 번역기형 (경쟁사) | 렌즈형 (BarkLens) |
|---|---|---|
| 출력 | "행복해요!" 한 문장 | 상황 확률 5개 + 3축 지문 + 근거 |
| 확신 | 단정 | 확신도 표기, 단발음은 낮게 |
| 개체 | 견종 평균 | 우리 강아지 기준선 학습 |
| 몸짓 | 카메라 자동 판독 주장 | 보호자가 보는 단서 체크 → 조합 판단 (v2에서 자동화) |
| 데이터 | 비공개 | 보호자 태그로 함께 만드는 데이터, 근거 논문 공개 |

**제품 원칙**
1. 투명성: 모든 판독에 "왜"를 붙인다 (특징값 + 문헌 근거).
2. 확률과 불확실성: 퍼센트와 확신도를 숨기지 않는다. 단발음·저SNR은 낮은 확신으로 표기.
3. 의인화 금지: 개는 사람과 다른 표정을 쓴다 (Caeiro 2017). "화났다"보다 "경계·위협 신호".
4. 온디바이스 우선: 소리는 기기에서 처리, 업로드는 명시적 동의.
5. 복지 우선: 반복되는 두려움·공격 신호는 전문가 상담을 권한다. 의료·행동 진단 아님을 명시.

| (B2B) 훈련사·행동 수의사 | 보호자 상담 | 객관적 기록과 시각화 | 대시보드 구독 |

## 6. 핵심 사용 시나리오

1. **초인종이 울린다** → 앱이 자동으로 짖음 7회를 잡는다 → 스펙트로그램에 낮고 거친 띠가 빠르게 반복 → "경계·위협 78%, 확신 높음" + 근거(음높이 340 Hz로 낮음, 거친 음색, 0.3초 간격) → 대응 팁("짖음이 멈춘 순간 보상") → 보호자가 "경계"로 태그.
2. **혼자 두고 외출** → 부재 모드 켬 → 90분간 낑낑 12회, 띄엄띄엄 짖음 5회 → 귀가 후 요약 "외로움·분리 신호 우세, 첫 20분 집중" → 주간 리포트에 누적 → 훈련사에게 내보내기.
3. **놀이 중 으르렁** → "으르렁, 짧고 느리게 박동, 높은 음 → 놀이 으르렁 가능성" + "몸짓 탭에서 플레이 바우가 있으면 놀이" 안내.
4. **낯선 개와 마주침** → 몸짓 탭에서 '왼쪽 편향 꼬리, 입 다물고 긴장, 정지' 체크 → "경계·위협(부정·고각성)" + "거리를 두세요".

## 7. 기능 정의

우선순위: **P0** = 샘플/MVP 필수, **P1** = v1(스토어 출시), **P2** = v2 이후.

### 7.1 소리 렌즈 (P0)
| 기능 | 설명 | 샘플 앱 구현 |
|---|---|---|
| 실시간 검출 | 마이크 입력에서 잡음 바닥 대비 문턱(기본 12 dB)으로 짖음 이벤트 자동 분할, 에너지 골짜기 기준 연속음 분리 | ✅ |
| 스펙트로그램 | 150 Hz–8 kHz 로그 주파수 축, 실시간 스크롤 | ✅ |
| 소리 종류 | 짖음·깽·낑낑·으르렁·하울링 | ✅ (규칙) |
| 3축 지문 | 음높이(F0, 개체 기준 대비 반음) · 음색(조화도/평탄도) · 리듬(짖음 간격) | ✅ |
| 상황 확률 | 외로움·경계·놀이·요구·두려움 5개, 고정 순서 막대 + 확신도 | ✅ |
| 근거 | 특징값 → 문헌 규칙 → 문장 | ✅ |
| 대응 팁 | 상황별 1문장 가이드 | ✅ |
| 파일 분석 | 녹음 파일 업로드 → 정적 스펙트로그램 + 이벤트 목록 | ✅ |
| 데모 | 합성음 5종으로 동작 확인 | ✅ |

### 7.2 몸짓 렌즈 (P0 체크리스트 → P2 자동)
- 25개 단서(꼬리·귀·얼굴·자세)를 체크하면 정서가·각성 평면에 표시, 상태 요약, 카밍/위협/두려움 안내, 단서별 출처 표시. (샘플 앱 ✅)
- P2: 카메라로 DogFACS 랜드마크·꼬리 궤적 자동 추출.

### 7.3 상황 태그 · 기록 · 리포트
- 판독 직후 "실제 상황은?" 태그 (P0 ✅) → 학습 데이터와 개인화의 원천.
- 세션 타임라인, 7일 상황별 스택 막대, 보호자 태그 일치율 (P0 ✅).
- 주간 리포트 푸시, 시간대 히트맵, 훈련사 공유 링크 (P1).

### 7.4 개인화 (P0 기본 → P1 고도화)
- 몸집 기준 음역(소형 850 / 중형 600 / 대형 420 Hz) → 기록 10회 이상이면 우리 강아지 중앙값으로 자동 보정 (샘플 앱 ✅).
- P1: 개체별 few-shot 적응(임베딩 + 보호자 태그).

### 7.5 부재 모니터링 (P1)
- 외출 모드: 백그라운드 녹음(개 소리 구간만 저장), 요약 알림, 낑낑/짖음 비율로 두려움 vs 좌절 성향 힌트 (Lenkei 2021).

### 7.6 가이드 · 전문가 연결 (P1)
- 상황별 행동 가이드 콘텐츠, 반복 경고 시 행동 전문가 상담 연결.

### 7.7 향후 (P2)
- 멀티모달(소리+영상), 소니피케이션(강아지 소리 패턴을 사람이 알아듣기 쉬운 음/진동으로 변환해 청각 피드백), 다견 개체 분리(개체 식별은 문헌상 52~68% 가능), 하드웨어 파트너(목걸이/홈캠) 연동.

## 8. UX 흐름과 화면 정의

### 8.1 정보 구조 (하단 5탭)
`듣기` · `몸짓` · `기록` · `근거` · `설정`

### 8.2 핵심 흐름
온보딩(이름·몸집·마이크 권한·한계 고지) → 듣기 시작 → 자동 판독 카드 → 태그 → 기록 누적 → 주간 리포트 → 가이드/전문가.

### 8.3 화면별 요소

| 화면 | 요소 | 비고 |
|---|---|---|
| 듣기 | 스코프(스펙트로그램 + 6초 포락선 + HUD) · 컨트롤(듣기/파일/데모) · 판독 카드(소리 종류, 상황, 확신, 레이더+3축 슬라이더, 상황 막대, 근거, 팁, 태그) · 세션(60초 타임라인, 상황 카운트, 목록) | 판독 카드는 항상 "왜"를 펼쳐 보여 줌 |
| 몸짓 | 단서 칩(그룹별) · 결과(정서가-각성 평면, 상태, 안내, 출처) | 단서 1개면 정확도 경고 |
| 기록 | 7일 타일 · 일별 스택 막대 · 최근 목록 · 내보내기/지우기 | 로컬 저장, 서버 없음 |
| 근거 | 규칙 표 · 논문 카드(DOI 링크, 앱 반영) · 데이터셋 | 신뢰의 근간 |
| 설정 | 이름·몸집·자동 기준선·민감도 · 한계 고지 | |

### 8.4 시각화 설계 원칙
- **스펙트로그램**은 "소리를 보이게" 하는 제품의 논지. 로그 주파수 축(150 Hz–8 kHz)으로 300–1,500 Hz 짖음 대역이 화면의 절반을 차지하게 한다.
- **3축 지문**: 슬라이더(수치·방향) + 레이더(한눈에 모양). 같은 강아지의 경계/놀이 지문이 다른 "모양"으로 보이게.
- **상황 막대**는 순서를 고정하고(색+이름+숫자 항상 병기) 1위만 굵게. 색은 검증된 카테고리 팔레트(색각 이상 대비 확인).
- **정서가-각성 평면**은 몸짓 결과의 위치를 점으로. 사분면 라벨은 개 행동학 용어.
- 문구는 "~일 수 있어요/~와 연관됩니다" 톤. 단정 금지.

## 9. 데이터와 AI 설계

### 9.1 신호 처리 파이프라인 (샘플 앱 = v0)

| 단계 | 방법 | 파라미터 |
|---|---|---|
| 입력 | 모노 Float32, 기기 샘플레이트(44.1/48 kHz) | 에코 제거·잡음 억제·AGC 끔 |
| 프레임 에너지 | 20 ms 프레임, 10 ms 홉, RMS dB | 잡음 바닥 = 최근 6초 20퍼센타일 |
| 이벤트 검출 | 바닥+12 dB 시작, 바닥+6 dB 종료(히스테리시스), 50 ms 지연, 30 ms 이내 병합, 9 dB 골짜기 분할 | 40 ms–4 s |
| F0 | NSDF(McLeod) 40 ms 창, 60–3,000 Hz, 명료도(clarity) | 이벤트 내 최대 12창 중앙값 |
| 음색 | 명료도 0.7 + (1−스펙트럼 평탄도) 0.3 | 0–1 |
| 스펙트럼 | 2048 FFT: 중심, 평탄도, 85% 롤오프, 5대역 비율 | |
| 리듬 | 4초 내 이벤트를 바우트로 묶고 시작-시작 간격 중앙값 | 0.2 s→1, 2.5 s→0 (로그) |
| 해석 | 5상황 목표값과의 가중 거리 → 가우시안 점수 → 소리 종류 사전확률 → 정규화 | σ=0.28 |
| 확신 | 1·2위 격차 0.45 + 바우트 길이 0.3 + SNR 0.25 | |

### 9.2 규칙 엔진 목표값 (문헌 기반)

| 상황 | 음높이 | 음색 | 리듬 | 근거 |
|---|---|---|---|---|
| 외로움·분리 | 0.72 (높음) | 0.75 (맑음) | 0.15 (느림) | Yin 2004; Lenkei 2021 |
| 경계·위협 | 0.20 (낮음) | 0.25 (거침) | 0.85 (빠름) | Yin 2004; Pongrácz 2006 |
| 놀이·흥분 | 0.70 | 0.65 | 0.70 | Pongrácz 2006 |
| 요구·관심 | 0.55 | 0.55 | 0.45 | Molnár 2008 (ball/walk) |
| 두려움·불안 | 0.80 | 0.30 | 0.25 | Pongrácz 2006, 2024 |

소리 종류 사전확률: 낑낑 → 외로움 1.6 · 두려움 1.5, 으르렁 → 경계 1.8 · 놀이 1.1, 하울링 → 외로움 1.8.

### 9.3 모델 로드맵

| 버전 | 구성 | 목적 | 지표 목표 |
|---|---|---|---|
| v0 (샘플) | 규칙 엔진 | 흐름 검증, 데이터 수집 시작 | 보호자 태그 일치 ≥ 55% |
| v0.5 | YAMNet(TFLite) 개 소리 검출 + 규칙 엔진 | 오탐(TV·사람 목소리) 제거, 배터리 | 오탐률 < 10% |
| v1 | 오디오 파운데이션 임베딩(YAMNet 1024-d / BEATs / Wav2Vec2) + 소형 헤드: 상황 5분류 + 각성·정서가 회귀 | 공개 데이터 부트스트랩 + 자체 태그 | macro-F1 ≥ 0.6 (5상황), 일치 ≥ 70% |
| v1.5 | 개체 적응: 보호자 태그 20개로 헤드 미세조정/프로토타입 네트워크 | 개체 특이성 흡수 | 개체별 +10%p |
| v2 | 멀티모달: 카메라(DogFLW 랜드마크, 꼬리 궤적) + 소리 late fusion | 몸짓 자동화 | 긍정/부정 ≥ 85% |

### 9.4 데이터 전략
- **부트스트랩**: Barkopedia(감정·검출·품종), EmotionalCanines(각성·정서가 1,400), AudioSet 개 클래스, Abzaliev 2024(14 소리 유형) — 라이선스 확인 후 사전학습·평가용.
- **자체 수집**: 앱 내 "실제 상황은?" 태그 (6종 + 기타), 상황 카드 가이드로 라벨 품질 확보. 국내 다빈도 견종(말티즈·푸들·포메라니안·믹스·진돗개) 편향을 관리.
- **라벨 체계**: 소리 종류(5) × 상황(6) × 각성·정서가(연속, 선택) + 메타(견종·몸집·나이·성별·환경).
- **목표량**: 베타 6개월, 2,000마리, 5만 이벤트, 태그율 30% 이상.
- **품질**: 태그 일치율 모니터링, 2인 검수 샘플 5%, 잡음·중첩(사람 목소리) 자동 필터.

### 9.5 평가
macro-F1(5상황), 각성·정서가 CCC, 보정 오차(ECE), 보호자 태그 일치율, 오탐/미탐률, 온디바이스 지연(< 300 ms), 배터리(부재 모드 1시간당 < 3%).

### 9.6 프라이버시·안전
온디바이스 기본, 업로드 옵트인, 사람 음성 구간 저장 금지(개 소리 검출 구간만), 삭제권·내보내기, 의료기기 아님 고지.

## 10. 기술 아키텍처

```
[모바일 앱 (PWA → Capacitor / React Native)]
  마이크 → 링버퍼(30s) → 검출기 → 특징 추출 → (v0 규칙 | v1 TFLite/ONNX 임베딩+헤드) → 판독 카드
  로컬 DB(SQLite/IndexedDB) ← 이벤트·태그·프로필
  부재 모드: 백그라운드 오디오 서비스(iOS Audio Background, Android Foreground Service)
        │ (옵트인) 개 소리 구간 + 라벨 업로드
[백엔드 (Supabase: Postgres · Storage · Auth · Edge Functions)]
  이벤트/태그 저장, 주간 리포트 생성, 공유 링크, 훈련사 대시보드
[ML 파이프라인]
  공개 데이터 + 자체 데이터 → 임베딩 추출 → 헤드 학습/평가 → 모델 레지스트리 → 앱 OTA 배포
```

- 현재 저장소가 Next.js 16 · React 19 · Tailwind 4 기반이므로 **Next.js PWA + Capacitor** 경로가 가장 빠르다. 샘플 앱(순수 HTML/JS)의 `dsp.js`·`knowledge.js`는 프레임워크 무관하게 그대로 이식된다.
- 네이티브 필요 시점: 백그라운드 녹음(부재 모드)과 배터리 최적화가 필요한 v1부터.

## 14. 결정이 필요한 사항

1. 1차 플랫폼: PWA 우선(빠름, 스토어 없음) vs 네이티브 우선(부재 모드) → **권고: PWA로 M1, Capacitor로 M4**.
2. 첫 타깃 견종군: 국내 다빈도 소형견(말티즈·푸들·포메) 집중 vs 전체 → **권고: 소형견 집중 후 확장**.
3. 데이터 수집 인센티브: Pro 무료 기간 vs 리포트 제공 → **권고: 태그 30개마다 Pro 1주**.
4. 하드웨어: 자체 개발 없음, 파트너 SDK 전략 → **권고: 앱 우선, 12개월 후 판단**.
